PIPELINE DE TEXTURING - WORKFLOW DE A A Z
==========================================

0. INSTALLATION (une seule fois) ............................. FAIT
------------------------------------------------------------------
  Double-clic sur F:\Pipeline\install.bat
  Mise a jour du pipeline : recuperer la derniere version du repo GitHub
  (branche claude/keen-heisenberg-we6ihj), puis relancer install.bat.


1. PREPARER UN ASSET DANS TRIPO3D ................................
------------------------------------------------------------------
  Pour chaque asset, depuis la MEME generation Tripo, telecharger :
    - la version Smart Low Poly EN QUADS (.glb) -> mesh du jeu
                                                 (UV bien plus propres qu'en triangles)
    - la version de base, detaillee (.glb)    -> source du relief
    - l'image de reference (.png)             -> lumiere neutre si possible

  Les ranger dans un dossier par asset, par exemple :
    F:\Pipeline\assets\robot01\robot01_low.glb
    F:\Pipeline\assets\robot01\robot01_high.glb
    F:\Pipeline\assets\robot01\robot01_ref.png


2. UV (depliage optimise) ................................ DISPONIBLE
------------------------------------------------------------------
  Ouvrir une invite de commandes dans F:\Pipeline, puis :

    texpipe\uv_optimize.bat assets\robot01\robot01_low.glb assets\robot01\robot01_uv.glb --texture-size 4096 --preview assets\robot01\apercu.png

  Verifier ensuite :
    - robot01_uv_uv_report.json : "status" doit valoir "OK"
    - apercu.png : les carres du damier doivent etre reguliers partout
    - robot01_uv_uv_layout.png : la disposition des ilots (rouge = probleme)

  Le fichier robot01_uv.glb est le mesh final du jeu pour la suite.
  Si le mesh est symetrique (cas general avec Tripo), une seule moitie est
  depliee et l'autre la reprend en miroir : deux fois plus de resolution.
  Options utiles (detail dans texpipe\blender\README_UV.md) :
    --symmetry off         textures differentes a gauche et a droite
    --quality seams        moins de coutures
    --hidden-density 1.0   meme resolution partout (dessous compris)


3. CALCUL DES CARTES DE GEOMETRIE ............................ DISPONIBLE
------------------------------------------------------------------
  Toujours dans F:\Pipeline :

    texpipe\bake_maps.bat assets\robot01\robot01_uv.glb assets\robot01\robot01_high.glb --texture-size 4096 --preview assets\robot01\apercu_bake.png

  Produit dans le dossier de l'asset (prefixe robot01_) :
    _normal.png     normal map (DirectX, pour Unreal)
    _ao.png         occlusion ambiante
    _curvature.png  courbure (aretes claires, creux sombres)
    _height.png     hauteur, _up.png orientation vers le haut
    _basecolor_high.png / _roughness_high.png / _metallic_high.png
                    couleurs Tripo reprojetees (guides pour l'etape 5)

  Verifier ensuite :
    - apercu_bake.png : le mesh de jeu (1re et 3e image) doit ressembler
      au HighPoly (2e et 4e)
    - robot01_bake_report.json : "pixels_missed_percent" faible
    - robot01_bake_check.png : en rouge, les zones ou le HighPoly n'a pas
      ete trouve (parties simplifiees du LowPoly ; quelques % c'est normal)

  Symetrique ou non : rien a regler. Si l'etape 2 a mis les deux cotes en
  miroir, un seul cote est calcule ; sinon, tout le mesh l'est.


4. COULEUR GUIDE PAR IA (MV-Adapter) ......................... DISPONIBLE
------------------------------------------------------------------
    texpipe\color_guide.bat assets\robot01\robot01_uv.glb assets\robot01\robot01_front.png

  Donner l'image de FACE : les images _Back, _Left, _Right du meme dossier
  sont trouvees automatiquement et remplacent les vues inventees par l'IA
  quand elles collent bien a la forme du mesh.
  Le premier lancement telecharge les modeles (~6 Go, dans F:\Pipeline\models).
  Produit :
    _views.png        6 vues generees (face, droite, dos, gauche, dessus, dessous)
    _color_guide.png  ces vues reprojetees sur les UV du mesh de jeu

  Verifier _views.png : les 6 vues doivent montrer le meme objet, fidele a
  la reference. Sinon, relancer avec une autre graine (--seed 7) et/ou une
  description en anglais (--prompt "dark metal robot, purple glowing lines").
  Une vue retouchee a la main peut etre reprojetee seule :
    ... --views assets\robot01\robot01_views.png


5. DECOUPAGE EN ZONES + VALIDATION ............................... A VENIR
------------------------------------------------------------------
  Le pipeline propose des zones numerotees ; tu indiques le materiau de
  chaque zone dans un petit fichier (1 a 2 minutes par asset).


6. COMPOSITION DES MATERIAUX ..................................... A VENIR
------------------------------------------------------------------
  Materiaux PBR reels + usure, salete, poussiere selon la geometrie.


7. EXPORT ET IMPORT UNREAL ....................................... A VENIR
------------------------------------------------------------------
  Textures BaseColor / Normal / ORM et import automatique dans le projet.


8. RETOUCHE MANUELLE (optionnel, assets heros) ...................
------------------------------------------------------------------
  ArmorPaint ou Blender.


EN ATTENDANT LES ETAPES 5 A 7
------------------------------------------------------------------
  Apres les etapes 2 et 3, le mesh robot01_uv.glb a ses cartes (normal map,
  AO, courbure) et l'ancienne texture Tripo reprojetee. Il peut etre texture
  a la main dans ArmorPaint ou Blender, ou importe tel quel dans Unreal
  (normal map : aucun reglage, elle est deja dans la convention d'Unreal).


EN CAS DE PROBLEME
------------------------------------------------------------------
  Envoyer le message d'erreur et, pour les UV, le fichier *_uv_report.json
  avec l'image *_uv_layout.png ; pour les cartes, *_bake_report.json avec
  *_bake_check.png et l'apercu.
